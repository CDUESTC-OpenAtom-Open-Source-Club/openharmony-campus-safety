# 正式测试版手动测试清单

## 测试账号

| 角色 | 账号 | 初始密码 |
|---|---|---|
| 管理员 | `admin` | `admin12345` |
| 安保人员 | `inspector` | `inspect123` |
| 学生 | `student` | `student123` |
| 教师 | `teacher` | `teacher123` |

这些账号用于本机测试版协同，不代表已接入学校统一身份认证。密码仅在首次初始化时生成派生值，应用本地不保存明文密码。

## M6 账号与权限回归

1. 使用学生账号登录，提交一条隐患；确认事件列表只显示该账号自己的上报。
2. 检查学生账号无确认、派单、任务中心和管理统计操作。
3. 退出并用管理员登录，确认能看到全部事件；确认学生刚提交的事件。
4. 在事件详情选择“巡检员一号”并下发，确认不会重复生成同一事件的任务。
5. 退出并用安保账号登录，确认只显示分配给 `inspector_001` 的任务。
6. 安保账号接单、填写处置结果并提交审核；确认不能自行审核。
7. 管理员登录并审核通过；再切回学生账号，确认事件进度和最终处理结果仍可查看。
8. 在“账号与安全”中修改密码、退出并使用新密码重新登录。
9. 关闭应用后重新打开，确认当前会话、事件、任务和处理结果没有丢失。

## M7 第一阶段：上报图片与操作历史

1. 学生账号进入隐患上报，从系统相册选择 1—3 张图片，确认页面显示预览。
2. 取消一次“重新选择”，确认原图片仍在；重新选择新图片，确认旧图片被替换。
3. 移除一张图片，确认预览消失；再次选择后提交上报。
4. 进入事件详情，确认“现场证据”能正常显示图片，“操作历史”包含上报人和上报时间。
5. 用管理员确认、派单，安保人员接单并提交结果，再用管理员审核通过；确认每个动作均追加一条历史。
6. 另建一条事件并驳回返工，确认历史中显示驳回原因。
7. 关闭并重启应用，确认图片和全部操作历史仍可读。

## M7 第二阶段：我的上报与处理进度

1. 学生账号登录后，确认首页显示“我的上报”和“我的最新上报”，底部入口显示“记录”。
2. 用学生和教师账号分别提交一条事件，确认两个账号只能看到自己的上报。
3. 分别使用“待确认”、“已确认”、“处理中”、“待审核”和“已完成”筛选，确认列表结果正确。
4. 打开各状态事件的详情，确认五节点进度轴与当前状态一致。
5. 管理员审核通过后切回上报账号，确认详情显示“最终处理反馈”；待审核时不应提前显示。

## 已知边界

- 当前为单设备本地账号体系，角色隔离是应用内保护，不替代服务端授权。
- 当前构建已通过 ArkTS 编译；云手机的系统相册交互、旧库迁移和重启持久化需按本清单实机验证。
- 当前图片能力覆盖上报现场证据；处理前后证据、服务卡片等在后续阶段继续实现。
